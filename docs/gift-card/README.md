## Size: 5 x 7 in, 0.125 in bleed (page 5.25 x 7.25 in)

Why this size: it is a standard US card and photo size, so any print shop quotes it and a standard 5 x 7 envelope fits it. It is big enough for the steps at 17 pt with a QR of 1.5 to 1.7 in, which a smaller card (4 x 6 in or A6) would make tight at that type size. The 5 x 7 trim fits Letter with room for crop marks, so it can also be printed at home on card stock and cut with a trimmer. The art runs 0.125 in past the trim so a slightly off cut shows no white edge. A shop that wants other bleed can be given the PDF as is and trims to 5 x 7.

PDF page size is 378 x 522 pt (5.25 x 7.25 in) for the cards and Letter for the sheets (checked with `pdfinfo`, one page each, fonts embedded).

Home print: Letter, print at **100% / Actual size**, not Fit to page, then cut on the crop marks.

Each QR sits on its own white tile with the full 4-module quiet zone inside the tile (error correction M). "Symbol" is the dark-module area; the tile is larger.

The TestFlight QR is deliberately **not a link**: it encodes the words "PLACEHOLDER - TestFlight public link not created yet. Do not print." in red, so a phone that scans it shows words and cannot open anything. The letter sheet for that back also says in its margin not to print it.

### Decode results

Every QR was decoded from the rendered files, not from the source URL: the 300 dpi card PNGs, the 150 dpi sheet PNGs, and a 300 dpi raster of every PDF (`pdftoppm`). All passed, with zxing-cpp. Full table in `decode-results.md`.

- web back: 1 of 1 decoded to the web URL. TestFlight back: 2 of 2 (the placeholder text and the web URL). Front: no QR, none found.
- Lower resolution, zxing-cpp: every QR still decoded at one third size (about 100 dpi on the cards, 50 dpi on the sheets). OpenCV, a weaker decoder, decoded all of them at full size and the web back down to one third.
- Dry run with a sample link (`https://testflight.apple.com/join/AbCd1234`, in a scratch copy, **not saved here**): the TestFlight QR turned black, the placeholder labels went away, and all QRs decoded to the right strings. A second run with no URL kept the sample link, as intended.
- `zbarimg` itself could not be installed in the sandbox that made these (no package), so the check used zxing-cpp and OpenCV. Not tested with a real iPhone camera or a printed copy: scan a print on Sun 25 Oct.

## When the TestFlight link exists

Apple approves a build, then in TestFlight create the public link (Open to Anyone) and send it to Claude; or run it yourself:

```bash
cd ~/projects/steampunk-shuffle
python3 docs/gift-card/make.py https://testflight.apple.com/join/XXXXXXXX
```

That one command makes the QR, drops the red placeholder, rewrites `back-testflight.html`, renders both backs and the three sheets to PDF and PNG, decodes every QR from the PNGs and the PDFs, and writes `decode-results.md`. It exits with code 3 if any QR fails. It refuses a link that does not look like `https://testflight.apple.com/join/...` (override: `--allow-any-url`). Later runs without a link keep the live link; `--placeholder` puts the placeholder back.

Needs Python 3.9+, Chrome (or Chromium or Edge; found automatically, or `CHROME=/path`), Pillow (`pip3 install pillow`, already in `tools/requirements.txt`), and for the decode check one of `brew install zbar`, `pip3 install zxing-cpp`, `pip3 install opencv-python-headless`. Without a decoder it still renders and says the check was skipped. It never runs git and writes only inside `docs/gift-card/`.

**Not tested on the Mac:** the PDFs and PNGs here were rendered in a Linux sandbox with Chromium. The macOS Chrome paths in `make.py` are not run yet. Fonts are embedded, so a Mac render should look the same. Run it once on Sun 25 Oct with the placeholder to find out, not on Thu 29.
