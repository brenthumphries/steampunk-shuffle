## What I worked on

Release 1.1, plan X-A2 (`docs/plans/monthly/14-saves-and-android.md` §6): send and receive a single ledger as a `.wheatstone` file. Branch `claude/release-1-1-x-a2`.

## What got done

- **Ledger file, save-file version 2.** `src/save/saveFile.ts`: `{ version: 2, ledgerId, ledgerName, summary, exportedAt, keys, sha256 }`, one ledger per file. `keys` is each per-game store's raw string by name, so a round trip is byte-identical. `sha256` comes from `src/save/sha256.ts` (synchronous, tested against the standard vectors). `parseIncomingSave` refuses a bad checksum, an unknown key name, a newer version and unrelated JSON with a plain message and writes nothing.
- **Old files still import.** The whole-save blob (version 1, and the blob that also called itself version 2) is told apart by shape (`pub`, no `keys`) and becomes a new ledger with no id of its own.
- **Send.** "Send this ledger" writes `<name>-<date>.wheatstone` and opens the share sheet: Capacitor Share and Filesystem on iOS, Web Share API with a file on the web, a download otherwise. `saveFileName` and `exportLedger` (`src/save/ledgers.ts`) now produce this file; the delete-a-ledger backup uses it too.
- **Receive.** `src/ui/receiveLedgerScreen.ts` and `receiveLedger`/`planReceive` in `ledgers.ts`. New id: added with the sender's id. Same id on the device: both summaries and dates, then Replace (backup first) or Keep both. Shelf full: pick one to replace, or cancel. Every replace shares a backup of the ledger being replaced and waits for `completed`, the same rule as delete.
- **Opening from outside.** iOS: `Info.plist` document type, exported UTI `com.brenthumphries.steampunkshuffle.ledger`, `LSSupportsOpeningDocumentsInPlace` false, plus `@capacitor/app`'s `appUrlOpen` in `src/native/incomingFile.ts`. Web: `file_handlers` in the manifest (`vite.config.ts`) and `launchQueue`. Android: `window.wheatstoneReceiveLedger(text)` is the hook, with a TODO for X-B2's intent filter; the e2e test uses it.
- **Privacy.** New e2e case in `tests/e2e/privacy.spec.ts` (share path: no request, no new key). `public/privacy.html` and `docs/app-privacy-answers.md` say what sending and receiving do. No new localStorage key.
- **Tests.** Unit: `tests/unit/save/ledgerFile.test.ts`, `tests/unit/ui/receiveLedgerScreen.test.ts`, web-share cases in `saveExport.test.ts`. E2e: `tests/e2e/ledgerFiles.spec.ts` (send then receive, same id, damaged file, opened from outside).

## Decisions made

- The new file's `version: 2` collides with the blob that X-A1 had already labelled version 2. Kept both readable, distinguished by `keys`. The prompt called the current format v1; the code says 2.
- Audio mute is device-wide, so it is not in a ledger file (the old blob carried it).
- The web file keeps MIME `application/json` so `canShare` accepts it.
