## What got done

- **Filed PT-33 and PT-34 in `PLAYTEST.md`** via `ss-playtest`, then moved
  both to its Resolved section once fixed, with the fix writeup inline.
- **PT-33: "Leave Game."** New button in the match topbar
  (`src/ui/matchScreen.ts`), shown via `MatchScreenOptions.leaveGame`,
  absent for the tutorial. Tapping it opens a confirm overlay with wording
  specific to the match kind (pickup: "pays out the same as a loss";
  tournament: "eliminates you from this tournament"), Cancel/Leave anyway.
  Leaving calls the screen's existing `onExit` with a synthetic
  `{ winner: otherPlayer(HUMAN), reason: "conceded" }` result. New
  `MatchResult.reason` member added in `src/engine/matchTypes.ts`;
  `main.ts`'s `finishPickupMatch`/`finishTournamentMatch` only branch on
  `winner`, so the existing loss-payout path (Checks, bracket elimination)
  needed no new code. `mountMatch` in `src/main.ts` passes
  `leaveGame: { matchKind: params.context.kind }` for both pickup and
  tournament matches.
- **PT-34: acknowledge gate.** Both timed holds in `afterCommit` (the
  opponent's Instant-card announce, `INSTANT_ANNOUNCE_MS`, and the general
  on-play/discard "resolving" hold, `holdMs`) still run their full existing
  duration, then stop auto-advancing. A `ready` flag reveals a "Continue"
  the player must tap; `pendingProceed` holds the `proceed()` closure the
  timer used to call directly.
- **New e2e coverage.** `tests/e2e/leaveGame.spec.ts` (tutorial has no
  button; pickup and tournament Cancel/Leave-anyway, with the pickup
  payout asserted against `localStorage`'s pub-state). Updated
  `instantAnnounce.spec.ts` and `onPlayAnimation.spec.ts` for the new
  Continue-tap flow.
- **Found and fixed a pre-existing e2e flake while shipping, unrelated to
  either fix.** Three assertions in `match.spec.ts` picked "the first
  tappable hand card" and expected it in `.board-row`, but a
  self-discarding Scheme/Headline (Inspector's Warrant, Séance) or a
  Location (The Parsonage Snug) never lands there. Confirmed via
  `git show 448eeba` that the pattern predates this session. Reproduced
  locally with a Playwright trace and on CI (Firefox, run `36276502770`).
  Fixed by excluding those three cards by name
  (`boardBoundTappableCard`); 25/25 clean runs on Firefox afterward.
- **Shipped via `ss-ship`, two commits, both green on all four CI
  browsers:**
  - `5918eda`: the PT-33/PT-34 fix.
  - `755db76`: the `match.spec.ts` flake fix, pushed separately after the
    first ship's CI run caught it.
  - Live at https://brenthumphries.github.io/steampunk-shuffle/, confirmed
    by Brent playing a match on his phone.
- Also had to clear a stale `.git/index.lock` (0 bytes, no `git` process
