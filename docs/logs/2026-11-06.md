## What I worked on

Release 1.1 step X-A1, the Ledger Shelf and namespacing migration (`docs/plans/monthly/14-saves-and-android.md` §2 and the X-A1 prompt in §6). Build agent on Sonnet, as the plan assigns.

## What got done

- **Ledgers.** `src/save/ledgers.ts`: the registry `ws:ledgers` (`activeId` plus `{ id, name, createdAt, lastPlayedAt, summary: { title, wins, collectionCount } }`), create, switch, rename, delete (refuses without `backedUp: true`), `MAX_LEDGERS = 4`.
- **Namespacing.** `src/save/storageKey.ts` is the only place keys are built: `storageKey(name)` gives `ws:<activeId>:<name>`. Pub, decks, tournaments, active match, tutorial and player are routed through it (booth, advent, gifts, ledger stats and the rest live inside the pub state, so they follow). `GLOBAL_KEYS` is the one list of device-wide keys (registry, `ws:backup:v1`, mute). `tests/unit/save/namespacing.test.ts` scans `src/` and fails on any storage call that is neither.
- **Migration (plan §2.3).** `initLedgers()` runs from `src/boot.ts` before `main.ts`. With no registry and an old save it writes `ws:backup:v1` (raw keys plus a normal export), copies every old per-game key into a new ledger named from the player name, then writes the registry with `migratedAt`. Originals stay 30 days, then a launch deletes them (via `today()`). Idempotent; an interrupted run re-uses the backup's ledger id. The beer mat shows once (queued in `runLaunchTasks`); Save & data gets "Restore the cellar copy" for the 30 days.
- **Ledger Shelf screen.** `src/ui/ledgerShelfScreen.ts`, opened from a new "Ledgers" hub button and from Save & data. Books with title, wins, cards, last played; the one in use marked; New, Switch, Rename, Delete (type the name; exports through `src/ui/saveExport.ts`, the code the Export save button now shares). Switching reloads the app.
- **Native.** `storageMirror` now mirrors `steampunk-shuffle:*` and every `ws:*` key and hydrates both.
- **Docs.** design.md §12.5; `public/privacy.html` and `docs/app-privacy-answers.md` list the three new key shapes; `privacy.spec.ts` accepts exactly the documented global keys and `ws:<uuid>:<one of six names>`.
- **Tests.** Unit: `tests/unit/save/ledgers.test.ts` (28, against a fixture `tests/unit/save/fixtures/currentRelease.json` built with the real save code: every key and value identical, originals untouched, idempotent, 30-day window, restore, isolation of wins/gifts/booth draws/decks/active match, max 4, delete needs backup), `namespacing.test.ts`, `ui/ledgerShelfScreen.test.ts`, mirror tests. E2e: `tests/e2e/ledgers.spec.ts` (two ledgers, a tutorial step in each, switching back and forth; delete; max four; migration and cellar restore; the 30-day cleanup).

## Decisions made

- **`storageKey` falls back to the old key when no registry exists.** Rejected: throwing, which would have meant rewriting about 40 unit tests that read keys directly. The app never runs in that state (boot settles the registry first).
- **Ledger name and player name are separate.** The hub's name box edits the player name; the shelf's Rename edits the ledger label. Rejected: keeping them in sync, which would make Rename on a non-active ledger write into another ledger's player key.
- **A new ledger skips the dedication** (`dedicationSeen: true`) and begins at the tutorial.
- **Ledger names are unique, ignoring case,** so Switch and Delete-by-typing are unambiguous.
- **The cellar backup stays after 30 days;** only the original keys are deleted, as the prompt says.
- **e2e seeding now writes a ledger, not old-style keys,** so the migration beer mat does not cover the hub in every spec. Inline specs got an in-page `L(name)` helper (a mechanical rewrite of about 20 specs); `{ legacy: true }` exercises the migration.
- **Restore uses an inline "Yes, restore it" step,** not `window.confirm`, which Playwright dismisses silently.

## Follow-up to X-A1 (branch `claude/release-1-1-x-a1-followup`)

Brent's Nov 6 decisions on the open questions above.

- **Tutorial exit.** `MatchScreenOptions.leaveToShelf` (`src/ui/matchScreen.ts`) puts a "Ledger Shelf" button in the tutorial match's top bar with a confirm ("Back to the shelf?"). `main.ts` passes it only when the registry holding more than one ledger. It never calls `onExit`, so the tutorial is not marked done; opening that ledger again deals the tutorial from the top (it was never resumable mid-match). The shelf's Back returns to the tutorial while it is unfinished.
- **Delete waits for the share.** `exportSaveFile` now returns `{ status, completed }`. In the native build it writes the file with Capacitor Filesystem (cache dir), shares it with Capacitor Share, and `completed` is true only when the share promise resolves; cancel or failure gives `completed: false`, no download fallback, and the shelf deletes nothing and says so. The web path is unchanged (a download counts as completed). Plugins are imported lazily, so the web build never loads them.
- **Plugins.** Added `@capacitor/share` and `@capacitor/filesystem` and hand-edited `ios/App/CapApp-SPM/Package.swift` to match what `cap sync` generates. `npx cap sync ios` was NOT run here (no macOS/Xcode); run `npm run cap:sync` on the Mac and commit any change to `Package.swift` / `Package.resolved`. Not tried on a device.
- **Migration backup** `ws:backup:v1` stays forever: stated in design.md §12.5 and `public/privacy.html`. No code change.
- **Tests.** Unit: `tests/unit/ui/saveExport.test.ts` (fake Share: completed, cancelled, write failure), a cancelled-backup case in `ledgerShelfScreen.test.ts`. E2e: a tutorial exit test in `ledgers.spec.ts` (one ledger shows no button; two ledgers, leave, switch back, return, tutorial deals again).
