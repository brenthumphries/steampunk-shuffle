## What I worked on

Release 1.1 step X-B1, install from the web (`docs/plans/monthly/14-saves-and-android.md` §3.1 and the X-B1 prompt in §6). Build agent on Haiku, as the plan assigns.

## What got done

- **Install page at `/install/`.** `install/index.html` (a Vite entry, Pages build only) with `src/install/installPage.ts`. It shows the Android, iPhone or desktop steps for the phone it runs on, an Install button when the browser has offered its prompt, and a QR code (`install/qr.svg`). Nothing on the page makes a network request.
- **In-game beer mat, once.** On Android Chrome, not yet installed, when the browser has offered its prompt: "Keep the Bridge on your home screen?" with an Install app button. It shows on the hub after the notices and the hint (`src/ui/pubHubScreen.ts`, wired in `src/main.ts`). Logic lives in `src/install/installPrompt.ts`.
- **Persistent storage, once.** `navigator.storage.persist()` is asked for once, after the web app first runs installed (`requestPersistentStorageOnce`).
- **Native bundle.** No install page and no install offer. Both checks are build-time (`import.meta.env.MODE === "native"`) and the page is left out of the native build's inputs in `vite.config.ts`.
- **Test fix (not in the prompt).** `expectArtLoaded` in `tests/e2e/birthday.spec.ts` read `img.complete` at once, so an image inserted a moment earlier could still be loading and fail the check. It now waits for each `<img>` to load or error (5 s cap) before judging it. The assertion is unchanged. It failed twice in full Native runs on the All Hallows' Wake portraits and passed in isolation.
- **Tests.** `tests/unit/install/installPrompt.test.ts` (11 tests: platform detection, the offer rules, the optional flags, the once-only storage request). `tests/e2e/install.spec.ts` (install page on Android and iPhone, the hub mat once on Android, absent in the native bundle).
- **Tooling.** `tools/makeInstallQr.ts` and `npm run install-qr`. `qrcode@1.5.4` and `@types/qrcode@1.5.5` added as devDependencies (exact versions).

## Decisions made

- **The two new flags live inside the existing player key** (`steampunk-shuffle:player`: `installOfferSeen`, `storageRequested`), not a new localStorage key. `privacy.spec.ts`'s documented-keys list and `public/privacy.html` are unchanged.
- **The QR is generated once and committed** rather than at build time. The URL is fixed, so the generator only needs rerunning if the Pages address changes. The prompt allowed either.
- **The beer mat is marked seen when shown,** not when answered. It never returns, but the install page and the browser's menu still offer the install.
- **The 30-day "Send this ledger" reminder is not built.** It waits for ledger transfer (X-A2), so `installPrompt.ts` says so in a comment.
