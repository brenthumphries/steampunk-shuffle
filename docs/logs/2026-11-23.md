## What got done

- **Sleeves registry.** `src/cosmetics/sleeves.ts` (`{ id, name, artId, source }`). `sleeve-the-bridge` is the default, always owned, art id `card-back`. Only the default is registered, and no pack has a `sleeveId`, so nothing is earnable on the live site until J-C.
- **Save.** `pub.ownedSleeves` and `pub.eventWins` inside `pub-state`, `sleeveId` per slot inside `deck-slots`; no new localStorage key, so privacy files are untouched. A save without them loads default-only (tested from the real `currentRelease.json` fixture); save-file v2 round-trips them, v1 and fieldless v2 files still import. `SAVE_FILE_VERSION` stays 2.
- **Deck builder and match.** A "Sleeve" picker per slot (`src/ui/deckBuilderScreen.ts`); the player's face-down board cards wear the selected slot's sleeve, the opponent's the default (`matchScreen.ts`, `main.ts` `selectedSleeve()`); a missing image falls back to the default art.
- **Earning.** `src/cosmetics/sleeveAward.ts`: each win (pickup or tournament, not Sir Charles) is counted against live events that have a `sleeveId`, dated by `today()`; 3 in one year's window awards the sleeve, once. The hub shows an unwrap and the beer mat "Sir Charles found these in the cellar..."
- **Fallback rule.** `resolveFixedPrize` in `src/tournaments/prizes.ts`: giftOnly fixed prize in a public build pays the event's first visitor's signature card (150 Checks as printed) if not owned, else 300 Checks; the tournament list shows it. `withEditionFilter` exported so a test-only tournament drives the seat fill (the giftOnly boss drops out and a Seasoned takes the seat).
- **Docs.** `docs/design.md` §17.5 (see Decisions). CLAUDE.md gotcha.
- **Tests.** 5 new unit files (`tests/unit/cosmetics/`, `tests/unit/tournaments/publicFallback.test.ts`, two in `tests/unit/ui/`) and `tests/e2e/sleeves.spec.ts` (picker with the default only, pre-sleeve save, default backs in a match).

## What I worked on (J-A)

January step J-A (real moon phases and Full Moon +N), started early on Brent's say-so. Branch `claude/aether-voyage-j-a`. No event pack, visitors or event cards: those are J-C.

## What got done

- **`src/sky/moon.ts`.** Meeus ch. 49 new and full moon instants (periodic terms, 14 planetary arguments, ΔT 2005-2050). Exports `moonPhase(date)` (8 named states, illumination 0-1), `isFullMoonNight(date)` (day before, of, after, in local time), `moonEventInstant`. No clock inside.
- **Full Moon +N.** `Keywords.fullMoon`, validator, `effectivePoints` (face-up only, stacks with Friend and Moonrise), `MatchState.fullMoon` set once by `createMatch({ startDate })`, AI nudge in `cardPotentialValue`, chip "Full Moon +N", House Rules entry, design.md §5.17. `matchScreen` passes `today()`; simulations and bracket sims pass nothing, so no moon.
- **Old saved matches.** `fullMoon` is optional; a saved match without it loads and reads as false (test in `activeMatch.test.ts`). No save-version change, no new localStorage key.
- **Hub moon.** `src/ui/hubMoon.ts` draws eight SVG states, glow on full; tap opens a beer mat from `src/sky/moonLines.ts` (phase title, Sir Charles line, plus the Hampstead line on full-moon nights). `?now=&preview=1` reaches it through `today()`.
- **Tests.** `tests/unit/sky/moon.test.ts`, `tests/unit/ui/hubMoon.test.ts`, Full Moon cases in `seasonalKeywords.test.ts`, property test now runs half its games on a full-moon night, `tests/e2e/moon.spec.ts` (full, new, waxing gibbous, dev clock).
